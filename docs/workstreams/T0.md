# T0: Product Foundation & Architecture

Owner expertise: Architecture. No individual assignment implied.

## Research question

Evaluate Excalidraw licensing, controlled editing hooks, Discord iframe constraints and GoDaddy VPS feasibility using versioned primary evidence.

## Required contract

Specify system boundaries, trust zones, command and event ownership, consistency invariants and ADR review process.

## Capability scope

### Product contract

- **Requirements and use cases**: Define moderator-led workshops, viewer participation, guild-owned boards and abuse cases; distinguish MVP from v1.0; record measurable availability, latency, capacity and recovery objectives without claiming measurements.

- **Interaction and system architecture**: Map Activity, API, bot, collaboration, database and assets; diagram data flows and trust boundaries; document transport, storage and identity ownership with ADR alternatives and handoffs.

### Technology and licensing

- **Editor feasibility and technology selection**: Compare Excalidraw integration hooks, read-only guarantees, serialization and custom extensions; evaluate React/TypeScript/Fastify and MySQL/MariaDB; pin evaluated versions and compatibility limitations.

- **License and supply chain policy**: Review MIT compatibility of direct and transitive dependencies, fonts, icons and imported assets; record SPDX identifiers, attribution, distribution obligations and upgrade policy before adoption.

### Developer foundation

- **Monorepo build and engineering conventions**: Define frontend, API, bot and shared contract package boundaries; configure reproducible installs, lint, type checking, formatting and versioned builds; reject cross-layer imports.

- **Local environment and configuration validation**: Provide environment schema with PORT integer 1–65535, NODE_ENV development/test/production, DATABASE_URL mysql scheme, DISCORD_CLIENT_ID decimal string and SESSION_SECRET minimum 32 characters; report missing names without secret values; test valid, missing and malformed input.

### Governance and architecture continuity

- **Governance and contribution policy**: Define maintainers, review roles, decision escalation, contributor conduct and issue ownership; document Definition of Ready and Done; preserve unassigned backlog visibility.

- **ADRs, threat model and architecture checks**: Maintain versioned decisions with alternatives and evidence; trace requirements to interfaces, security controls and acceptance tests; detect undocumented boundary changes in PR review.
