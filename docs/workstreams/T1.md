# T1: Discord Activity & Identity

Owner expertise: Discord Integration. No individual assignment implied.

## Research question

Verify current Discord Activity launch, proxy mappings, OAuth scopes, guild/channel context and supported desktop/browser/mobile clients.

## Required contract

Define OAuth exchange, session identity, guild/channel provenance, role refresh and revocation trust contract.

## Capability scope

### Activity bootstrap

- **Application registration and Activity lifecycle**: Document Developer Portal setup without creating credentials in source; initialize Embedded App SDK, wait for ready, handle launch/close and client disconnect; surface unsupported contexts.

- **Discord proxy and client compatibility**: Configure URL mappings and proxied HTTP/WSS routes; validate desktop, browser and explicitly supported mobile clients with versioned evidence; record unsupported touch or iframe behavior.

### OAuth and sessions

- **Secure authorization code exchange**: Perform server-side one-time code exchange; validate redirect/context binding, state and applicable PKCE requirements; keep Discord credentials and refresh tokens out of iframe storage and logs.

- **Session issuance and expiration**: Bind session to Discord user and verified guild/channel context; rotate session identifiers, enforce TTL and logout; reject expired, revoked and replayed credentials across HTTP and WSS.

### Guild membership and roles

- **Verified guild and channel identity**: Resolve membership and channel access server-side; reject client-asserted guild membership and cross-guild identifiers; define least-privilege bot/API scopes and missing-access behavior.

- **Role caching and permission refresh**: Fetch current roles with bounded cache TTL; invalidate on relevant events and failures; fail closed for privileged mutations when membership freshness cannot be established; test role removal during editing.

### Resilience and platform behavior

- **Identity reconnection and token renewal**: Recover SDK/session lifecycle after sleep, token expiry and reconnect without privilege widening; handle user/guild context changes and partial authentication safely.

- **Discord API errors and rate limits**: Respect retry-after and route/global buckets; bound retries with jitter and cancellation; distinguish forbidden, missing access, invalid token and transient outage without leaking tokens.
