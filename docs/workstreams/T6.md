# T6: Collaboration Modes & Presentation

Owner expertise: Frontend & Canvas. No individual assignment implied.

## Research question

Specify presenter and follow behavior across Discord clients, user navigation and concurrent mode changes.

## Required contract

Define authoritative mode state machine and permission matrix for moderated, open, locked, presentation and request-to-draw modes.

## Capability scope

### Mode state machine

- **Moderated, open and locked modes**: Persist mode selection and enforce mode-specific editing rights on server; distinguish all-writer collaboration from moderator-only and locked state; publish current mode to clients.

- **Request-to-Draw mode transitions**: Integrate queue/grant policies with mode transitions; define pending request and grant lifecycle when switching modes; reject stale mode revision changes.

### Presentation authority

- **Presenter designation and controls**: Allow authorized moderator to designate/revoke presenter and start/end presentation; prevent forged presenter events; preserve editing authorization separately from viewport authority.

- **Follow Presenter and viewport synchronization**: Distribute bounded presenter viewport state with sequence number; allow explicit follow/unfollow; restore personal viewport and avoid leaking another board's navigation.

### Viewer experience

- **Viewer navigation during presentation**: Expose follow status, zoom/pan and rejoin controls with keyboard access; document navigation behavior for viewers and writers while preserving mode policy.

- **Presentation UI and accessibility**: Provide mode/presenter indicators, control labels and reduced-motion transitions; support narrow Discord layouts and announce meaningful state changes without cursor noise.

### Transition correctness

- **Concurrent mode and presenter changes**: Serialize mode transitions with expected revision; reject stale requests; fence mutation authorization against current mode and recover authoritative state after reconnect.

- **Mode and presentation acceptance**: Test each role across each mode, concurrent presenter changes, reconnect, follow/unfollow and revoked presenter; ensure viewers never acquire write permission through presentation.
