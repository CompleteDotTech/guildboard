# T13: Documentation, Community & Release

Owner expertise: Maintainer & Documentation. No individual assignment implied.

## Research question

Validate contributor, guild administrator, moderator and end-user journeys for missing documentation and release support assumptions.

## Required contract

Specify documentation ownership, versioning, release criteria and community governance with evidence-linked acceptance.

## Capability scope

### Developer and architecture docs

- **README, architecture and setup guides**: Explain actual implementation state, local prerequisites, package boundaries, auth/data flows and configuration; test setup on clean environment; never advertise unimplemented functionality as available.

- **Discord Developer Portal and API guides**: Document application registration, scopes, URL mappings, SDK lifecycle, bot installation and OpenAPI/WS contracts with verified versions and safe credential handling.

### User and operator docs

- **GoDaddy deployment and troubleshooting guide**: Document mandatory Linux VPS, DNS/TLS/WSS, migrations, secrets, backups, monitoring and rollback; distinguish planned examples from tested commands and actual deployment evidence.

- **Administrator, moderator and end-user manuals**: Describe role mapping, board management, Grant the Pen, requests, lockdown, modes, drawing, save status, history and accessible alternatives with permission-aware troubleshooting.

### Community and maintenance

- **Security policy, contributions and governance**: Publish private security reporting route, review expectations, Code of Conduct and decision process; use actual known maintainers only; define issue/PR templates and welcoming contribution scope.

- **Versioning, changelog and release notes**: Adopt semantic versioning and compatibility/deprecation policy; generate reviewed release notes with migrations, known issues, license notices and verified test/deployment evidence.

### Release and future delivery

- **MVP and stable release execution**: Prepare tagged artifacts only after corresponding release gates pass; record production acceptance separately from merged PRs; verify rollback/support docs and publish reproducible release provenance.

- **Future enhancements and maintenance backlog**: Collect measured post-release needs, optional managed Node hosting research and nonessential enhancements; prioritize independently without substituting them for mandatory GoDaddy VPS delivery.

## Evidence and handoff

Implementation, validation and documentation are separate work items. Link accepted PRs, actual reviewers, exact tested revision/environment and consumer handoffs here when they exist. No workstream is verified by this planning document.
